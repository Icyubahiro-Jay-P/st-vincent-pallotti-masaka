## RELIABILITY / ABUSE-RESISTANCE (needs an external service, not just code)
# From an `open code` audit (2026-09-22). The code-only items from that
# audit (cache news/sitemap queries, rate-limit unsubscribe, cap
# unbounded form arrays, dedupe slug-collision loops, DB query timeout)
# are already implemented -- see lib/events.ts, lib/slug.ts, lib/db/index.ts.
# These four need picking/provisioning a third-party service first.
- Move the admin-publish newsletter send (lib/newsletter/send-event-newsletter.ts,
  called synchronously from saveEvent in
  app/admin/(dashboard)/events/actions.ts) off the request path via a
  queue (Vercel Queues or Inngest) -- today a single publish click blocks
  the response on 100+ DB reads + Resend API calls for large subscriber
  lists. Needs picking and provisioning a queue provider.
- Replace the DB-backed checkRateLimit (lib/rate-limit.ts) with an edge
  KV/Redis-backed limiter (Vercel KV or Upstash) so a GET flood can't add
  DB write pressure by way of the rate limiter itself. Needs provisioning
  that service.
- Add a vercel.json Firewall/WAF config (rate limits, bot rules) -- none
  exists today. Needs Vercel Firewall setup/API access.
- Remaining dynamic public pages: /[locale]/admissions, /news, /news/[slug],
  /gallery and /newsletter/unsubscribe still render per request (searchParams
  or forms). Everything else is now prerendered per locale since getLocale()
  reads the URL (next/root-params) instead of cookies().
- public/llms.txt and public/llm.txt conflict with app/llms.txt/route.ts and
  app/llm.txt/route.ts (Next returns 500 for /llms.txt in dev). Keep one of
  each pair.
